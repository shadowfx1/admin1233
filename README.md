# راية القانون — موقع جاهز للنشر على Cloudflare Pages

## هيكل المشروع (Static + Functions)

```
.
├── public/                 ← كل ملفات الموقع الثابتة (ارفع هذا كمخرجات البناء)
│   ├── index.html
│   ├── images/             ← كل الصور (شعار + شركاء + صور الفريق + ...)
│   ├── admin/              ← لوحة التحكم
│   ├── services/
│   ├── articles/
│   ├── contact/
│   ├── locations/
│   └── en/
├── functions/              ← Cloudflare Pages Functions (مطلوبة لتعمل لوحة الأدمن)
├── migrations/             ← مخطط قاعدة D1
├── wrangler.toml           ← pages_build_output_dir = "public"
├── hash-password.mjs
└── README.md
```

**مهم جداً:** لوحة التحكم (`/admin/`) تعمل فقط بعد ربط قاعدة D1 وإضافة متغيرات البيئة (انظر الأسفل). بدونها لن تتمكن من تسجيل الدخول أو رؤية الطلبات.

# دليل التشغيل والنشر — لوحة تحكم راية القانون

هذا الدليل مكتوب بلغة مبسطة لمالك المكتب أو المسؤول التقني. يشرح ملفات النظام، وطريقة إنشاء قاعدة البيانات، ورفع الموقع إلى GitHub ثم نشره على Cloudflare Pages.

> **مهم:** لوحة التحكم لا تظهر في أي صفحة من صفحات الموقع العام، ولا يوجد رابط لها في القوائم. مسارها المباشر هو `/admin/`، ولا يمكن فتح صفحاتها إلا بعد تسجيل الدخول.

---

## 1) ما هو كل ملف وأين يوضع

الملفات التي تُرفع إلى GitHub هي **محتويات** المجلد الرئيسي للمشروع (وليس المجلد نفسه):

| المسار | وظيفته |
|---|---|
| `public/index.html` وبقية صفحات الموقع داخل مجلد public/ | الموقع العام كما هو (عربي/إنجليزي)، بدون أي تغيير في التصميم |
| `admin/index.html` | صفحة تسجيل الدخول إلى لوحة التحكم |
| `admin/dashboard.html` | الصفحة الرئيسية للوحة: بطاقات الإحصاء وأحدث الطلبات |
| `admin/requests.html` | إدارة طلبات الاستشارة: بحث، تصفية، تغيير الحالة، ملاحظات داخلية، أرشفة |
| `admin/team.html` | إنشاء حسابات المحامين وتحديد صلاحياتهم (لمالك المكتب فقط) |
| `admin/reports.html` | التقارير وتصدير ملف CSV |
| `admin/settings.html` | بيانات الحساب، تغيير كلمة المرور، معلومات النظام |
| `admin/assets/admin.css` | تنسيقات لوحة التحكم (معزولة عن الموقع العام) |
| `admin/assets/app.js` | سكربت اللوحة المشترك (حماية الواجهة، الاتصال بالـ API، التنبيهات) |
| `functions/api/...` | واجهات الخادم على Cloudflare Pages (تسجيل الدخول، الطلبات، الفريق، التقارير، التصدير) |
| `functions/lib/core.js` | الثوابت والتحقق وتشفير كلمة المرور وتوقيع الجلسات |
| `functions/lib/store.js` | استعلامات قاعدة البيانات (متوافقة مع D1 وPostgreSQL) |
| `functions/admin/_middleware.js` | **حماية صفحات `/admin`** على Cloudflare: يمنع فتح أي صفحة إدارية دون جلسة صحيحة |
| `migrations/0001_init.sql` | مخطط قاعدة البيانات (الجداول والفهارس) |
| `wrangler.toml` | ربط قاعدة D1 باسم `DB` عند النشر عبر Git |
| `.dev.vars.example` | مثال لمتغيرات البيئة للتجربة المحلية (لا يحتوي على كلمات مرور حقيقية) |
| `contact/contact-form.html` | نموذج الاستشارة المركزي الذي تستخدمه كل صفحات الموقع |
| `tools/hash-password.mjs` | أداة توليد بصمة آمنة لكلمة المرور (تُشغَّل على جهازك فقط) |
| `README.md` | دليل الموقع العام وتعديل صفحاته |

### كيف يعمل النموذج الآن
1. يملأ العميل النموذج في الموقع ويضغط **إرسال**.
2. يُرسل الطلب إلى `/api/requests` بعد التحقق من الحقول.
3. يتحقق الخادم من البيانات، ويُنشئ رقمًا مرجعيًا مثل `RAY-2026-0001`، ويحفظ الطلب في قاعدة البيانات.
4. تظهر للعميل رسالة: «تم استلام طلبك» مع رقم المرجع، ويستطيع متابعة الطلب عبر واتساب.
5. يظهر الطلب في لوحة التحكم مباشرة ضمن **طلبات الاستشارة**.

> إذا تعذّر الاتصال بالخادم (مثل فتح الملفات دون نشر)، يتحول النموذج تلقائيًا إلى واتساب فقط، ولا يُظهر أي رقم مرجعي ولا يدّعي أن الطلب وصل.

## 2) إعداد قاعدة بيانات Cloudflare D1

1. افتح لوحة Cloudflare: <https://dash.cloudflare.com>.
2. من القائمة اختر **Storage & Databases** ثم **D1 SQL Database** ثم **Create database**.
3. اكتب الاسم: `rayat-alqanoon` ثم اضغط **Create**.
4. انسخ **Database ID** الظاهر في صفحة القاعدة.
5. افتح ملف `wrangler.toml` وضع المعرّف مكان `PUT-YOUR-D1-DATABASE-ID-HERE`:
   ```toml
   [[d1_databases]]
   binding = "DB"
   database_name = "rayat-alqanoon"
   database_id = "xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx"
   ```
6. أنشئ الجداول بإحدى طريقتين:
   - **من لوحة Cloudflare:** صفحة القاعدة ← تبويب **Console** ← الصق محتوى الملف `migrations/0001_init.sql` ← **Execute**.
   - **من جهازك (إن كان Node.js مثبتًا):**
     ```bash
     npx wrangler d1 execute rayat-alqanoon --remote --file=./migrations/0001_init.sql
     ```
7. **ملاحظة:** النظام ينشئ الجداول تلقائيًا عند أول استخدام إذا لم تكن موجودة، لكن تنفيذ الملف أعلاه هو الطريقة الموصى بها.

## 3) متغيرات البيئة (كلمة مرور المالك ومفتاح الجلسات)

افتح مشروع Cloudflare Pages ← **Settings** ← **Environment variables** ← **Add variable** (Production و Preview):

| الاسم | القيمة | ملاحظات |
|---|---|---|
| `ADMIN_USERNAME` | `admin` | يمكن تغييره إلى أي اسم مستخدم تريده |
| `ADMIN_PASSWORD_HASH` | بصمة كلمة المرور | الطريقة الموصى بها، انظر أدناه |
| `ADMIN_PASSWORD` | كلمة المرور كما هي | بديل أبسط للإعداد الأولي فقط |
| `SESSION_SECRET` | نص عشوائي طويل | 32 حرفًا على الأقل، ولا يُشاركه أحد |
| `OWNER_NAME` | `مالك المكتب` | الاسم الظاهر داخل اللوحة |

### توليد بصمة كلمة المرور (الموصى به)
على جهازك مع Node.js:
```bash
node tools/hash-password.mjs "كلمة-مرور-قوية-جديدة"
```
سيطبع سطرًا يبدأ بـ `pbkdf2:100000:...` — انسخه كاملًا إلى قيمة `ADMIN_PASSWORD_HASH`.
لتوليد `SESSION_SECRET` يمكنك استخدام:
```bash
node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"
```

### بيانات الدخول الأولية
- اسم المستخدم: `admin`
- كلمة المرور الأولية: `RayatLaw@2026`

> **غيّرها فورًا بعد أول دخول** من صفحة **الإعدادات ← تغيير كلمة المرور**. تُحفظ كلمة المرور الجديدة بصيغة مشفّرة داخل قاعدة البيانات وتتقدم على قيمة البيئة. لا تكتب كلمة المرور في أي ملف ترفعه إلى GitHub.

### ربط قاعدة البيانات بالمشروع
- في حالة النشر عبر GitHub يكون الربط من ملف `wrangler.toml` (اسم الربط `DB`).
- في حالة الرفع اليدوي: **Settings** ← **Functions** ← **D1 database bindings** ← Variable name: `DB` ← اختر قاعدة `rayat-alqanoon`.

## 4) الرفع إلى GitHub

1. افتح <https://github.com> ← **New repository** ← الاسم مثلًا `rayat-alqanoon` ← **Create repository**.
2. اضغط **uploading an existing file**.
3. اسحب **محتويات** مجلد الموقع كما هي (وليس المجلد نفسه):
   `index.html`، `about.html`، `team.html`، `services/`، `articles/`، `locations/`، `contact/`، `en/`، `images/`، **`admin/`**، **`functions/`**، **`migrations/`**، `wrangler.toml`، `README.md`، `README_DEPLOY.md`، `robots.txt`، `sitemap.xml`، `favicon.ico`.
4. **لا ترفع** أي ملف يحتوي كلمات مرور: `.env`، `.dev.vars`، أو مجلدات النسخ الاحتياطي.
5. اضغط **Commit changes**.

أو عبر الأوامر إن كان Git مثبتًا:
```bash
git init
git add .
git commit -m "Rayat Al Qanoon website + admin dashboard"
git branch -M main
git remote add origin https://github.com/USERNAME/rayat-alqanoon.git
git push -u origin main
```

---

## 5) النشر على Cloudflare Pages

1. <https://dash.cloudflare.com> ← **Workers & Pages** ← **Create** ← **Pages** ← **Connect to Git**.
2. اختر المستودع `rayat-alqanoon` ← **Begin setup**.
3. الإعدادات:
   - Framework preset: **None**
   - Build command: **اتركه فارغًا**
   - Build output directory: **`/`**
4. **Save and Deploy**.
5. أضف متغيرات البيئة (القسم 3) وربط D1 (القسم 2)، ثم **Retry deployment** أو نفّذ Commit جديدًا لتطبيق الإعدادات.
6. افتح `https://<project>.pages.dev/admin/` وجرّب الدخول.

> الأفضل استخدام HTTPS دائمًا؛ ملف تعريف الجلسة محمي بخصائص `HttpOnly` و`Secure` و`SameSite=Strict`، ولن يعمل بشكل صحيح على اتصال غير مشفر.

---

## 6) اختبار سريع بعد النشر

1. افتح الموقع العام ← صفحة **اتصل بنا** ← أرسل نموذجًا تجريبيًا.
2. تأكد من ظهور رقم مرجعي مثل `RAY-2026-0001`.
3. ادخل إلى `/admin/` ← **طلبات الاستشارة** ← يجب أن يظهر الطلب.
4. افتح الطلب وغيّر حالته ثم أضف ملاحظة داخلية.
5. من **التقارير** صدّر ملف CSV وافتحه في Excel.
6. من **الفريق والصلاحيات** أنشئ حساب محامٍ مع تحديد فرع واحد، ثم سجّل الدخول به في نافذة مستقلة وتأكد أنه يرى طلبات ذلك الفرع فقط ولا يستطيع فتح صفحة الفريق.
7. سجّل الخروج، ثم حاول فتح `/admin/requests.html` مباشرة — يجب أن يعيدك النظام إلى صفحة الدخول.

## 7) الأمان — ملخص ما تم تطبيقه

- كلمة المرور لا تُخزَّن كنص صريح في ملفات الموقع، بل بصمة PBKDF2 بـ 100,000 دورة وملح عشوائي.
- الجلسة عبارة عن رمز موقّع بـ HMAC-SHA256، صالح 8 ساعات، داخل كوكي `HttpOnly` لا يمكن لسكربتات الصفحة قراءته.
- جميع واجهات الـ API تتحقق من الجلسة على الخادم؛ لا يمكن قراءة أو تعديل الطلبات دون تسجيل دخول.
- صلاحيات المحامين تُطبَّق في قاعدة البيانات (فرع/خدمة)، وليس في الواجهة فقط.
- صفحات `/admin` محمية على مستوى الخادم عبر `functions/admin/_middleware.js` قبل إرسال أي ملف.
- محاولات الدخول الخاطئة تُقيَّد بعد 6 محاولات لكل 15 دقيقة، وتُسجَّل في سجل التدقيق.
- الطلبات العامة محدودة بخمسة طلبات لكل 10 دقائق لكل جهاز، مع حقل مصيدة للبوتات.
- رؤوس حماية إضافية للمسار الإداري: `X-Frame-Options: DENY`، `noindex`، ومنع التخزين المؤقت.
- جميع العمليات الحساسة (دخول، إنشاء حساب، تغيير حالة، حذف، تصدير) تُسجَّل في جدول `audit_log`.

**حدود يجب معرفتها:** أي كود يُرسل إلى المتصفح يمكن الاطلاع عليه، لذلك لا تضع أي كلمة مرور أو مفتاح داخل HTML أو JavaScript. كل الأسرار في متغيرات بيئة Cloudflare فقط. ولا تشارك بيانات دخول اللوحة إلا مع المصرح لهم.

## 8) النسخ الاحتياطي والتحديث

- **نسخة احتياطية للطلبات:** من صفحة **التقارير** صدّر CSV دوريًا، أو من Cloudflare D1 استخدم **Export** لتنزيل نسخة كاملة من قاعدة البيانات.
- **تغيير الأسرار:** من Cloudflare Pages ← Settings ← Environment variables، ثم أعد النشر.
- **نسيت كلمة مرور المالك:** حدّث `ADMIN_PASSWORD_HASH` في Cloudflare ببصمة جديدة (القسم 3) وأعد النشر.
- **تغيير رقم الهاتف أو واتساب:** في صفحات الموقع الثابتة كما هو موضح في `README.md`.

## 9) حل المشكلات الشائعة

| المشكلة | السبب المحتمل | الحل |
|---|---|---|
| رسالة «النظام غير مهيأ» عند الدخول | متغيرات البيئة غير مضافة | أضف `ADMIN_PASSWORD_HASH` (أو `ADMIN_PASSWORD`) و`SESSION_SECRET` ثم أعد النشر |
| الدخول ينجح لكن الصفحات تعيدك للدخول | `SESSION_SECRET` تغيّر بين طلبين أو غير مضبوط | ثبّت نفس القيمة في Production و Preview |
| «حدث خطأ في الخادم» عند إرسال النموذج | لم يتم ربط قاعدة D1 باسم `DB` | أضف ربط D1 كما في القسم 2 |
| النموذج يفتح واتساب فقط | واجهة `/api/requests` غير منشورة | تأكد من وجود مجلد `functions` في المستودع |
| الطلبات لا تظهر لمحامٍ | صلاحياته محددة بفرع أو خدمة أخرى | عدّل صلاحياته من صفحة الفريق بصفة المالك |
| خطأ 429 | محاولات دخول خاطئة متكررة | انتظر 15 دقيقة، أو صحّح بيانات الدخول |
